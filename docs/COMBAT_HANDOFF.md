# Combat implementation handoff

Implemented pure C# `Sapphire.CombatWorld`, `Vec2`, actor/projectile/event state and `Sapphire.Tests.CombatChecks.RunAll()`. No Unity dependency. Simulation is 60 Hz and the application owns elapsed-time accumulation and pause. Coordinates are [0,20] by [0,11]; presentation subtracts (10,5.5).

Commands `Attack`, `Cast(0..3)`, `Dodge` return rejection reasons without consuming resources on rejection. Basic projectile combos, bounded input buffer, four level-gated spells, shield absorption, regeneration, collision-aware blink/dodge, swept projectile hits, goblin melee, spirit projectiles, wolf dash, elite melee, and a two-phase boss are implemented. Enemy A* uses .25-unit cardinal grid cells and caches a waypoint for 12 ticks. Boss alternates area attack, dash, and (second phase) summoning.

Drain `Events` after simulation, route `Killed` once into campaign persistence using its unique `Id` and `EnemyKind`; combat does not grant inventory or XP itself. Player death wins over boss death when both events occur in the same step; application must evaluate `Player.Dead` before success settlement. `SetStats` preserves current HP with the maximum-HP delta, or fully heals when requested. `Restore` is only called after a potion transaction persists.

`EnterZone` clears enemies, projectiles, event queue, attack and temporary defensive states, and AUTO. Cooldowns remain across travel. Town detection uses `town`; boss uses `boss`/`dungeon3`; elite uses `elite`/`dungeon2`; other names spawn regular field sets. Root should use canonical zone mapping. Public obstacle collection allows authored maps to replace initial rectangles. Actor definitions and zone spawns currently live in this small module; expanding content should extract these into validated definitions before scaling the catalog.

Verification: compiled with Windows .NET Framework C# compiler and executed RunAll through reflection. Tests cover normalized movement, boundaries, blink wall blocking, locked/cooldown/mana command atomicity, shield expiry, projectile damage, unique kill rewards, event draining, wall-blocked hits, dodge attack-phase gates, enemy and boss telegraphs, phase-two summons, and A* navigation.

Known limits: no separation steering between actors, so enemy sprites may overlap; projectiles have fixed circular collision footprints; dash telegraphs need directional rendering from locked facing and distance (a circle alone would be an inaccurate cue). Animation interpolation remains presentation responsibility. Balance has not been playtested on mobile. Tests access internal timing fields and must compile in the same assembly as domain (current no-asmdef setup) or receive an explicit friend assembly.
