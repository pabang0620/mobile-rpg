# 모듈별 구현 설계

## M0 시작 흐름과 마을 허브 — 구현됨
로그인 → 서버 선택 → 캐릭터 선택 → 사파이어 광장 → 달빛 회랑 출정. 로그인/서버는 로컬 스텁이며 마을은 안전 지역이다. 상세 계약은 `docs/modules/M0_FRONT_FLOW_AND_TOWN.md`.


모든 모듈은 **명세 고정 → 최소 구현 → 규칙 검사 → 실제 씬 배선 → 플레이 캡처 → 인계 갱신** 순서로 닫는다. 앞 모듈의 공개 계약을 다음 모듈이 사용하며 화면 코드가 전투·보상 수치를 직접 바꾸지 않는다.

## M0 전투장 수직 슬라이스 — 완료
사용 목적은 에셋과 실제 플레이 규칙이 같은 화면에서 작동하는지 확인하는 것이다. `BattleSession`이 이동/공격/자원/사망/보상을 소유하고 `BattleScreen`은 입력과 표시만 담당한다. AUTO, 수동 우선권, 1회 명중, 회피 무적, 1회 보상, 새 run 격리가 검사됐다.

## M1 전투감과 캐릭터 표현
목표는 법사가 원본 캐릭터로 계속 인식되면서 횡스크롤 플랫폼 전투에서 던파형 타격감을 갖게 하는 것이다. 보행은 좌우, 세로 변화는 점프·중력·발판만 사용한다.

- 입력: 이동축, 공격/스킬 명령, 대상 후보, `AttackDefinition` 데이터.
- 출력: startup/active/recovery 상태, hit-stop, knockback, 경직, 슈퍼아머, 캔슬 가능 창, 방향·지면 기준점.
- 에셋: idle 8, run 8, 기본공격 16, 피격 4, 다운 6, 기상 6, 사망 8, 스킬별 핵심 포즈와 분리 VFX. 프레임마다 동일한 발 기준선과 지팡이 길이를 유지한다.
- 기술: 판정 트랙을 애니메이션 그림과 분리한 ScriptableObject로 만들고 프레임 번호 대신 초 단위 이벤트를 저장한다. 60Hz 규칙 시뮬레이션과 렌더 보간을 구분한다.
- 검토 주의: 이미지 크기 변화로 사거리가 바뀌면 실패다. 투명 여백·잘림·가짜 체크무늬·다른 셀 잔여물·좌우 반전 시 장식 오류를 자동 검사한다.
- 완료 기준: 세 가지 기본 연계가 같은 입력으로 재현되고, 명중/무적/캔슬 경계 검사가 통과하며, 실제 빌드 60초 영상에서 캐릭터 튐과 잔상이 없다.

## M2 자동사냥 의사결정
목표는 플레이어가 개입하지 않아도 전투가 진행되며 수동 조작 시 즉시 주도권을 돌려주는 것이다. 상세 계약은 `docs/modules/M2b_AUTOHUNT_DECISION_TECH_SPEC.md`(파일명이 `M2`가 아니라 `M2b`인 이유: 기존 `M2_COMBAT_HUD_REDESIGN.md`와 접두 충돌을 피하기 위함).

- 입력: 감지된 적, 이동 가능 영역, 스킬 비용/쿨다운, HP/MP, 위험 예고.
- 출력: 이동·대상·스킬·회피 의도. 실제 피해 적용은 M1 전투기가 담당한다.
- 기술: 우선순위 규칙과 짧은 상태 머신을 데이터로 구성한다. 0.2초마다 판단하되 현재 행동의 취소 계약을 지킨다. 2초 무진행 시 재탐색, 5초 무진행 시 안전 위치 복귀를 기록한다.
- 검토 주의: AUTO가 숨은 보너스 피해를 받지 않는다. 수동 입력 3초 유예, 위험 회피, MP 절약 기준을 로그로 설명할 수 있어야 한다.
- 완료 기준: 10분 soak에서 멈춤·벽 끼임·중복 보상 없이 전투가 지속되고 AUTO ON/OFF 저장 정책이 명세와 일치한다.

## M3 던전 런과 방 진행
목표는 입장→일반방→정예/이벤트→보스→결과의 한 판 흐름을 만드는 것이다.

- 입력: 던전 정의, 방 그래프, 웨이브 정의, 입장 비용, 난이도.
- 출력: 현재 방/웨이브, 문 잠금, 완료 조건, 런 결과 원장.
- 기술: `DungeonRun`은 재시작 가능한 seed와 방 상태를 소유한다. 보상은 전투 중 임시 원장에 쌓고 결과 확정 시 한 번만 영구 저장한다.
- 검토 주의: 앱 종료·재도전·보스 동시 사망에서 중복 보상이 없어야 한다. 방 배경은 시차 레이어와 전투 바닥 마스크를 별도 에셋으로 둔다.
- 완료 기준: 한 던전을 자동/수동 모두 끝내고 실패·재도전·강제 종료 복구 검사가 통과한다.

## M4 장비·성장·경제
목표는 사냥 보상이 다음 전투 선택을 바꾸는 성장 루프를 제공하는 것이다.

- 입력: 아이템 정의, 드롭 테이블, 강화 비용, 플레이어 소유 원장.
- 출력: 장착 스냅샷, 전투 파생 능력치, 소비/획득 거래 기록.
- 기술: 아이템 ID와 인스턴스 ID를 분리한다. 모든 화폐 변화는 reason code와 transaction ID를 가진 단일 서비스로 통과시킨다.
- 검토 주의: 화면 닫기·연타·저장 재시도에서 중복 소비가 없어야 한다. fixture 수치를 정식 테이블에 섞지 않는다.
- 완료 기준: 획득→비교→장착→강화→전투력 변화가 저장/재실행 뒤 유지되고 경제 불변식 검사가 통과한다.

## M5 레이드
목표는 자동사냥으로 성장한 캐릭터가 패턴 학습과 빌드 선택을 시험받는 장기 목표를 만드는 것이다.

- 입력: 보스 phase, 패턴 타임라인, 경고 영역, 부위/그로기, 입장과 보상 규칙.
- 출력: 예고→대응→피해→phase 전환→정산 이벤트.
- 기술: 패턴 선택은 seed 기반으로 재현 가능하게 하고 서버 권한을 붙일 수 있는 명령/결과 경계를 유지한다. 싱글 fixture에서 먼저 검증한다.
- 검토 주의: 시각 예고와 실제 판정 시간/범위가 일치해야 한다. AUTO는 편의 기능이며 핵심 즉사 패턴을 무조건 해결하지 않는다.
- 완료 기준: 3단계 보스 한 종을 수동 공략 가능하고 AUTO는 일반 구간을 돕되 패턴 개입 이유가 분명하다.

## M6 메타 UI와 모바일 마감
목표는 전투, 성장, 던전, 레이드 흐름을 한 손 조작과 작은 화면에서 읽히게 연결하는 것이다.

- 기술: 화면별 presenter가 도메인 snapshot을 읽고 command만 보낸다. safe area, 글자 확대, 색각 보조, 터치 크기 48px 이상을 공통 규칙으로 둔다.
- 에셋: 평면형 반투명 차콜/회색 프레임과 청색 활성 상태, 버튼 9-slice, 탭/배지/희귀도, 로딩/빈 상태/오류 상태를 한 세트로 제작한다.
- 완료 기준: 16:9·20:9·태블릿 기준 캡처와 실제 터치 기기에서 정보 잘림·중복 입력이 없다.
