# 후속 모델 실행 지침

## 우선순위

사용자의 최신 지시 → 새 프로젝트 AGENTS.md → 이 기획 패키지의 제품/시스템 계약 → 현재 작업 명세 → 원본 참고 문서. 현재 사용자는 planning을 요청했으므로 구현은 재개 지시를 받은 뒤 진행한다.

원본 횡스크롤 AGENTS.md와 복제된 BattleSession/BuildGame/로그를 새 설계 근거로 사용하지 않는다. 기존 파일은 참고 자료이고 새 구현의 검증 결과가 아니다. 패키지 내 계약이 충돌하면 구현 전 해당 결정과 영향을 기록해 일관되게 수정한다. 큰 제품 방향 변경은 사용자에게 확인하되, 정해진 계약 안의 함수 분할/테스트 fixture 같은 구현 선택은 스스로 처리한다.

## 하위 모델 시작 프롬프트

> outputs/PLANNING_START_HERE.md와 planning/01_PRODUCT.md, 02_SYSTEM_CONTRACTS.md, 03_EXECUTION.md, 05_AGENT_PLAYBOOK.md를 읽어라. 현재 요청은 P{번호} 한 작업이다. 관련 에셋 작업이면 04_ASSETS.md도 읽어라. 인계에서 선행 작업의 실제 검증 증거를 확인한 뒤 진행하라. 처음에 목표, 수정할 파일, 입력/출력 시그니처, 상태 소유자, 테스트 사례, 씬 연결 지점을 docs/tasks/P{번호}.md에 명시하라. UI에 게임 수치를 두지 말고, 미완성 기능을 임시 연출로 완료 처리하지 마라. 규칙 테스트, 실제 연결, 실행 검증을 수행하고 실패하면 원인을 수정하라. 작업 종료 전에 변경 파일, 검사 명령과 결과, 캡처, 미검증 사항, 다음 작업 ID를 HANDOFF에 기록하라. 계획의 기능을 생략하거나 다른 엔진으로 대체하지 마라.

```text

새 공개 타입/메서드 정확한 시그니처:

소유하는 상태 / 읽기만 하는 상태:

성공 시나리오 Given/When/Then:
실패·경계 시나리오 Given/When/Then:

```

## 잘못 구현하기 쉬운 규칙

- 이동은 XY 자유 보행, 점프/중력/발판을 추가하지 않는다.
- 기본공격은 메이지의 3단 마법 연계다. 무단으로 검사 직업/검 콤보로 바꾸지 않는다.
- 저장은 전체 거래 경계, UI 버튼의 직접 gold 변경 금지.
- 던전 드롭은 임시, 물약 소비는 유지, 성공 정산은 한 번만.
- 죽은 적 애니메이션이 남아 있어도 타격/보상 대상이 아니다.
- 스킬 부족 자원/쿨다운 거절 시 어떤 자원도 변하지 않는다.
- 프레임/애니메이션은 피해 시점의 권한이 없다.
- 동일 명령의 키보드와 터치 구현을 별도로 만들지 않는다.
- MonoBehaviour 하나에 전투/퀘스트/상점/저장을 몰아넣지 않는다.
- 생성 배경 한 장과 기존 캐릭터 흔들기만 연결한 결과를 완성 게임으로 보고하지 않는다.
- 구현되지 않은 기능 버튼과 서버 선택 스텁으로 제품 범위를 부풀리지 않는다.

## 인계 양식

```text
현재 기준 문서 버전:
완료한 작업 ID와 상태:
구현된 사용자 행동:
수정/추가 파일:
실제 실행한 검사(명령·종료코드·결과 파일):
실행하지 못한 검사와 이유:
알려진 오류와 재현:
변경한 공개 계약 / 결정 로그 ID:
다음 작업 ID:
다음 모델이 먼저 읽을 파일(최대 5개):
```

모델 교체 시 이전 설명을 신뢰하기 전에 파일과 검사 결과를 확인한다. 기능 변경이 없다면 이미 통과한 전체 검사를 의미 없이 반복하지 않는다. 변경 영향이 있는 테스트와 아직 미검증인 항목부터 수행한다.
