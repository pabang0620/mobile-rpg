# 슬라임 왕국 승인 시안 기반 타일

## 원본과 제작 방식

내장 imagegen으로 승인 맵 시안과 별도의 소재·오브젝트 원본을 생성했다.
`client/Assets/Sapphire/Art/World/Modular64/Sources/`에 보존한다.

- `ApprovedSlimeKingdomConceptV2.png`: 사용자가 승인한 배치/미술 참고. 런타임 배경으로 사용하지 않는다.
- `EnvironmentMaterialsV2.png`: 1536×1024, 512px 소재 3열×2행. 위쪽 잔디/흙/물, 아래쪽 석재 상판/절벽/그림자 참고.
- `EnvironmentObjectsV2.png`: 1536×1024 RGBA 나무/다리/계단/유적/소품. 투명 픽셀의 RGB에 녹색이 남아 있지만 알파가 분리되어 있다.

소재와 오브젝트 원본은 SHA-256으로 고정한다. 원본 교체 시 해시와 추출 위치를 함께 검토한다.
오브젝트는 지정 위치에서 연결된 알파 성분을 추출하고 64px 배수 footprint에 맞춘다.
투명 출력 픽셀의 RGB는 0으로 정리한다. 완성 맵을 조각내는 방식은 사용하지 않는다.

## 생성 프롬프트 핵심

소재: 승인된 슬라임 왕국 시안의 팔레트와 고밀도 픽셀아트를 유지한 잔디, 따뜻한 흙길,
청록색 흐르는 물, 이끼 낀 석재 상판, 절벽 면의 독립 소재 시트. 동일한 직교 3/4 시점과
광원, 텍스트/격자/UI/캐릭터 없음. 64×64 모듈 소재로 가공할 수 있는 넓은 내부 영역.

오브젝트: 승인 시안의 활엽수/침엽수/고목, 세로 목조 다리, 석조 계단, 이끼 낀 벽/기둥,
성소, 상자, 통나무, 그루터기, 바위, 꽃, 갈대를 서로 겹치지 않는 RGBA 시트에 생성.
투명 배경과 전체 실루엣을 보존하며 동일한 픽셀 밀도/광원/시점을 유지.
후속 배경 제거 요청에서는 모든 피사체 위치·색·모양을 보존하고 배경 알파만 제거.

## 재생성

`Sapphire.EditorTools.ModularTiles.ApprovedEnvironmentBuild.Build`

Ground → Elevation → Stairs → Water → Decorations → 독립 연결 씬 → SlimeKingdom 순서다.
각 단계의 기존 안정 ID, CSV, Sprite rect/64 PPU 및 경계 검사를 유지한다.
실제 씬 렌더링은 `verification/slime-kingdom-overview.png`와 입구 캡처로 확인한다.
게임 실행 파일은 별도의 `SapphireBuildPlayer.BuildWindows`로 갱신한다.

## 2026-09-26 적용 결과

- 승인 원본에서 추출한 나무, 고목, 기둥, 유적 벽, 성소, 상자, 꽃, 바위를 적용했다.
- 다리는 B004 중앙 판재/난간과 B005/B006 양끝을 별도로 추출한다. 전체 다리를 매 셀마다 반복하지 않는다.
- 물/고지대/절벽은 원본 소재의 연속 샘플링을 사용한다.
- TS08_River_Banks_64.png 및 BK001~BK047을 추가했다. 물 점유 마스크로 수변 안쪽에 석벽을 생성하며
  실제 인접 RGBA 검사를 수행한다. 모서리를 포함한 연결부에 투명 테두리를 두지 않는다.
- 지도에서는 물 위 다리 칸에 수변벽을 배치하지 않는다. 기존 통행/전투 위치를 유지한다.
- 독립 코드 검토 LGTM, Unity 전체 생성 종료 0 및 저장 씬 검사 통과.
- 실제 씬 전체 캡처로 다리 중앙 반복 연결, 수변벽 연속성, 원본 오브젝트 투명 배경을 확인했다.

최종 결과는 승인 시안의 소재를 사용한 모듈형 맵이다. 시안과 픽셀 단위로 동일한 배치는 아니며,
기존 40×30 이동 격자와 1칸 다리 폭을 유지한다. 물과 잔디의 소재 반복감은 남아 있다.
