|---|---|---|---|

### 근본 원인 3가지
1. **기준 해상도 방향이 SSOT와 반대.** 문서는 가로 1280x720인데 구현은 세로 720x1280(폐기한 실험 프로젝트 값이 `DECISIONS.md`에 확정처럼 기록됨). P1, P2, 카메라 줌, HUD 위치 계산이 전부 여기서 파생.
2. **Pixel Perfect Camera가 이 아트 스타일에 맞지 않음.** 정수 줌만 허용하므로 창 크기에 따라 화면에 보이는 타일 수가 24개/16개/10개로 널뛰고, 페인팅풍(바이리니어) 아트에는 픽셀 스냅 이점이 없음. 이미 `pixelSnapping=false`로 꺼둔 상태라 사실상 경고만 내는 부품.
3. **실측 대상이 틀린 측정.** 셀 경계는 쟀지만 프레임 "개구부"는 안 잼(P3), 버튼 지름 대비 호 간격을 검산 안 함(P4).

## 3. 개선 계획 (실행 순서)

### Phase 1. 기반 재정립 - 가로 1280x720, 카메라 교체
- `CanvasScaler.referenceResolution`을 (1280, 720), `matchWidthOrHeight`는 0.5 유지.
- D1(b): `PixelPerfectCamera` 제거. `CameraFollowRig`에 `verticalTilesVisible = 9`(orthographicSize = 4.5)와 **맵 경계 클램프**(카메라 뷰 사각형이 24x18 맵 밖으로 못 나가게) 추가. 결과: 1080p에서 1타일=120px, 캐릭터 약 130px(현재 72px).
- 빌드는 사용자 플레이용은 **비-Development 빌드**로 전환(개발용 오버레이 제거). 개발 빌드 플래그는 별도 옵션으로 남김.
- 기본 창은 **1280x720 창모드**(PlayerSettings 기본 해상도 + 레지스트리 잔여 창크기 삭제). 사용자 피드백 "켜주는 창이 너무 크다"(2026-09-15).
- Phase 2 추가: 스킬 아이콘은 프레임 안에서 중심·크기를 실측해 맞춘다(아이콘 콘텐츠 바운딩박스 중심 = 프레임 중심, 아이콘 지름 = 프레임 안쪽 지름의 약 62%). 사용자 피드백 "아이콘 정렬이 어색하다".
- `docs/DECISIONS.md`의 "세로 720x1280" 결정을 정정 기록.
- 검증: 1280x720 / 1920x1080 / 1936x1048(사용자 창) 세 해상도에서 스크린샷 -> 보이는 타일 수와 캐릭터 픽셀 높이 측정.

### Phase 2. HUD 재배선 (SSOT 52행 배치 그대로)
- 좌상단 HP/MP/레벨: 프레임 개구부를 픽셀 실측(트랙의 어두운 영역 바운딩박스)해서 Fill 앵커 산출. Fill 스프라이트는 개구부 안쪽 단색 영역만 잘라 외곽선 제거. MP바는 같은 프레임을 청색 게이지로 1개 추가(SSOT: HP/MP/레벨).
- 우하단: 큰 기본공격 버튼 중심으로 **스킬 4개** 부채꼴(반지름 200, 100도~190도, 3간격 30도 -> 중심간 103px > 지름 96px, 겹침 0). 질주/회피/물약/AUTO는 부채꼴 밖 별도 가로 열(SSOT: "회피/물약/AUTO"). **키 힌트 라벨(1~5, J)은 전부 제거**(사용자 지시 2026-09-15) - 키보드 단축키 자체는 유지하되 화면에 표시하지 않는다.
- 이동 스틱을 `MovementStickGold.png`(베이스 링/노브 2셀)로 교체, 크기 160.
- 잔디 반복 패턴 제거(셀 좌표 해시로 변종 3종 + 90도 회전 섞기)도 이 Phase에서 함께 처리(지형 빌더만 건드림).
- 상단 중앙 지역명(SSOT: 지역/보스 HP 자리) 텍스트 슬롯 예약.
- 검증: 각 요소 스크린샷 + 버튼 중심 간 거리 계산표.

### Phase 3. 메뉴 오딘식 재설계 (D2 확정 후)
- 에셋 신규 생성: 어두운 반투명 세로 패널, 섹션 헤더 바, 항목 아이콘(가방/장비/퀘스트/설정 4종 + 잠금 슬롯용 자물쇠 1종), 골드 톤 유지.
- 구조: 우측 슬라이드 패널, 섹션 헤더 + 5열 아이콘 그리드(아이콘 위, 라벨 아래), 잠금 슬롯은 회색+자물쇠.
- 코드: `MainMenuPanel`을 데이터 주도(`MenuSectionDefinition[]`)로 바꿔 항목 추가 시 코드 수정 없이 확장.
- 현재 `MenuPanelFrameGold.png`(세로 텍스트 목록용)는 폐기.

### Phase 4. 이동 스틱·월드 마감
- 스틱: 골드 링 + 사파이어 노브 에셋 생성 후 교체(크기 160으로 축소).
- 잔디: 셀 좌표 해시로 변종 3종 + 90도 회전 4종을 섞어 반복 패턴 제거.
- 커밋 `9d2a71d`가 추가한 `WorldRegionVillageGrassland-v1.png`(통짜 배경, `-v1` 접미사)는 용도 확인 후 채택/폐기 결정(별도 보고).

### Phase 5. 검증 규약 변경 (이번 사고의 재발 방지)
- **검수는 Phase 1~3 개발·수정을 전부 마친 뒤 한 번에** 한다(사용자 지시 2026-09-15, 토큰 절약). Phase 1은 컴파일·테스트·씬 파싱·커밋까지만, Phase 2와 3은 에이전트 1개가 연속 구현. 플레이어 빌드와 스크린샷은 전 작업 종료 후 1회만.
- 그 1회는 반드시 **실제 빌드 실행 -> 창 스크린샷 -> Fable이 직접 확인** 후 완료 보고. 컴파일/테스트/파일 파싱만으로 "완료"라고 하지 않는다.
- 측정은 "셀 경계"가 아니라 "화면에 보여야 하는 영역"(개구부, 버튼 지름 대비 간격)을 잰다.
- Fable 검수 통과 후 사용자 손테스트 1회.
